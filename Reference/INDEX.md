## How to Use This Knowledge Base

### For Learning Sessions

**Before session:**
1. Check Progress_Tracker.md for this week's goals
2. Review relevant concepts in Concept_Library.md
3. Have Learning_Plan_Master.md open for phase context

**During session:**
1. Work on learning goal
2. Take notes on new concepts
3. Use Code_Review_Template.md for code feedback

**After session:**
1. Update Progress_Tracker.md with time and learnings
2. Add new terms to Concept_Library.md
3. Commit code to GitHub

---

### For Code Reviews

**Workflow:**
1. Write code
2. Copy Code_Review_Template.md
3. Fill in all sections thoroughly
4. Paste in learning chat with Claude
5. Review feedback
6. Make changes
7. Document learnings in Progress_Tracker.md
8. Update Concept_Library.md with new patterns

---

### For Weekly Planning

**Monday Morning:**
1. Open Progress_Tracker.md
2. Review last week's progress
3. Set 3-5 specific goals for this week
4. Schedule learning blocks on calendar
5. Identify any resources needed from Reading_List.md

**Friday Afternoon:**
1. Update Progress_Tracker.md with week's work
2. Rate the week (1-5 stars)
3. Note wins and challenges
4. Prepare questions for next week
5. Update phase completion checklist

---

### For Phase Transitions

**Completing a phase:**
1. Review Phase Completion Checklist in Progress_Tracker.md
2. Verify all deliverables completed
3. Do monthly review in Progress_Tracker.md
4. Read next phase in Learning_Plan_Master.md
5. Adjust timeline if needed
6. Set Week 1 goals for new phase

## Critical Reminders

**For Claude interactions:**
- Use TEACHING MODE for learning (makes you think)
- Use EXPLAINER MODE for urgent work issues (direct answers)
- Always bring specific problems, not vague requests
- Try solving yourself first, then ask for help

**For documentation:**
- Write in your own words, don't copy/paste
- Include concrete examples from your work
- Update as understanding deepens
- Focus on practical application

**For progress:**
- Sustainable beats fast
- Adjust plan as needed - it's not gospel
- Celebrate small wins
- Document both successes and failures
