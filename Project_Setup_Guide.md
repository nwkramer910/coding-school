## How to Use This System

### Weekly Workflow

**Monday Morning (15 minutes):**
1. Copy Progress_Tracker_Template.md → `Progress_Week_XX.md`
2. Set this week's goals from Learning Plan
3. Plan your 15 hours

**During the Week:**
- Update daily log each day (5-10 minutes)
- Track what you learned, blockers, questions
- Keep it brief but consistent

**Friday End-of-Week (30 minutes):**
1. Complete week summary section
2. Note accomplishments and challenges
3. Preview next week
4. Update running phase progress

---

### When Learning New Concepts

**Use Concept Library:**
1. Open Concept_Library_Template.md
2. Add new entry for concept you learned
3. Write definition in your own words
4. Include example from your code
5. Save updated version

**Why This Matters:**
- Reinforces learning by explaining
- Creates personal reference
- Tracks your growth
- Shows what you've mastered

---

### When Writing Code

**Before Starting:**
1. State what you're building
2. Ask Claude questions to test your understanding
3. Try implementing yourself first

**When Stuck:**
1. Document exactly where you're stuck
2. Use Code_Review_Template.md structure
3. Share specific error messages
4. Ask targeted questions

**After Completing:**
1. Fill out Code_Review_Template.md
2. Request review from Claude
3. Document what you learned
4. Add new concepts to Concept Library

---

### When Using Resources

**From Reading List:**
1. Check Reading_List_and_Resources.md for current phase
2. Note which sections to focus on
3. Track what you've read in Progress Tracker
4. Add new useful resources you discover

## Chat Organization Strategy

### In Learning Project, Create These Chat Types:

**"Week X - [Focus Area]" Chats:**
- One chat per week
- Focus on that week's objectives
- Easier to find specific topics later
- Example: "Week 1 - Script Mapping"

**"Code Review - [Script Name]" Chats:**
- Dedicated chats for code reviews
- Use Code_Review_Template
- Easy to reference later
- Example: "Code Review - MAID Processor v2"

**"Concept Deep Dive - [Topic]" Chats:**
- When you need to deeply understand something
- Go down rabbit holes safely
- Example: "Concept Deep Dive - CTEs"

**"Quick Questions" Chat:**
- For rapid-fire small questions
- Don't pollute focused chats
- Quick lookups and clarifications

## Getting Help

### When to Ask Claude:

**Always Ask For:**
- Concept explanations
- Code review
- Debugging help
- Best practices
- Resource recommendations

**Ask Before:**
- Starting major code
- Making schema changes
- Committing to approach
- When confused

### How to Ask:

**Good Question:**
"I'm trying to implement a CTE for analyzing unit movements. I understand CTEs create temporary result sets, but I'm not sure if I should use WITH or a subquery for this case. Here's my current query: [code]. What would you recommend and why?"

**Less Helpful Question:**
"How do CTEs work?"

**Best Question:**
"I read about CTEs in the PostgreSQL docs. I understand they create temporary named result sets that exist only for the query. But I'm confused about when to use them vs. subqueries. Can you explain the practical difference with an example from my unit_positions table?"
